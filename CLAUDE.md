# deskos — настольный помощник на ESP32 (CYD)

> Файл памяти проекта. Читать в начале каждой сессии. Обновлять при изменении решений.

## Что строим

Настольное устройство-помощник: ESP32 + дисплей + кнопки, постоянно под питанием на столе.
Оболочка устройства работает как **мини-ОС**: лончер, список установленных виджетов,
пользователь сам добавляет/удаляет приложения-виджеты (погода, курсы валют, напоминания)
**без перепрошивки и без компиляции**.

Терминология: это не ОС в строгом смысле (планировщик уже есть — FreeRTOS внутри ESP-IDF).
Мы строим **shell + app runtime + app store**. Настоящий продукт здесь — стабильный API
виджета и формат приложения, а не оболочка сама по себе.

## Железо (проверено на живой плате, не из даташита)

Плата: **ESP32-2432S028R** («Cheap Yellow Display», CYD), 2.8" 320x240.

| Параметр | Значение |
|---|---|
| Чип | ESP32-D0WD-V3, **revision v3.1**, dual-core Xtensa LX6, 240 МГц |
| Flash | **4 МБ** (Boya, mfr 0x68, dev 0x4016), 3.3 В по strapping |
| PSRAM | **НЕТ** (~300 КБ свободной heap после LVGL+WiFi+TLS) |
| MAC | `44:1d:64:f3:39:0c` |
| USB | CH340 (VID 1A86 / PID 7523) → **COM13** |

### Распиновка (подтверждена по двум источникам)

| Периферия | Пины |
|---|---|
| Дисплей ILI9341 | SPI2/HSPI: SCK 14, MOSI 13, MISO 12, CS 15, DC 2, RST — нет, подсветка **21** (LEDC) |
| Тач XPT2046 | CLK 25, MOSI 32, MISO 39, CS 33, IRQ 36 |
| microSD | SCK 18, MOSI 23, MISO 19, CS 5 |
| RGB LED | R 4, G 16, B 17 — **активный низкий уровень** |
| LDR (фоторезистор) | 34 |
| Динамик | 26 |
| **Свободные GPIO** | **22, 27, 35** — и всё. GPIO35 только вход, **без внутренних pull-up** |

### ⚠️ Конфликт SPI-шин — важнейшее архитектурное ограничение платы

Тач (25/32/39/33) и SD (18/23/19/5) формально оба «VSPI», но с **разными пинами**.
Один SPI-контроллер не обслуживает два набора пинов; доступных шин у ESP32 всего две.
SDMMC-периферия не спасает — её слот-пины (14/15/2) конфликтуют с дисплеем.

**Принятое решение:** SPI2 → дисплей, SPI3 → SD (ей нужна пропускная способность),
тач → **программный SPI (bitbang)**, свой драйвер в `components/bsp/bsp_touch.c`.
XPT2046 тихоходный (~2 МГц), bitbang для него достаточен.
Побочный плюс: не нужен сторонний компонент `esp_lcd_touch_xpt2046`.

### ⚠️ CH340 и авто-ресет — почему хост-канал по WiFi, а не по USB

На плате штатная схема авто-ресета через DTR/RTS (ею пользуется esptool). Любая программа,
открывающая COM13, **перезагружает ESP32**. При уходе ПК в сон и особенно при выходе из сна
USB пере-энумерируется → устройство будет ребутиться каждое утро.

**Решение:** канал «устройство ↔ ПК-агент» — по **WiFi** (mDNS + WebSocket).
USB-serial только для прошивки, логов и первичной настройки. Не боевой транспорт.

## Принятые архитектурные решения

1. **Нативный ESP-IDF, не Arduino и не Tasmota.** Tasmota+Berry+HASPmota рассмотрена и
   отклонена: мы строим свой лончер, свой манифест, свою систему биндов и свой протокол
   с ПК-агентом — в Tasmota всё это уже есть и всё чужое, пришлось бы бороться по всем
   четырём пунктам. Оставлена как источник идей по декларативному UI.
   MicroHydra и ESP-Brookesia отклонены: рассчитаны на ESP32-S3 с PSRAM.
2. **UI на LVGL 9** + `esp_lvgl_port` (только для дисплея и LVGL-таска; indev'ы регистрируем
   сами, т.к. тач у нас bitbang).
3. **Раскладка по ядрам:** WiFi/TLS на core 0, LVGL на core 1. Без PSRAM это единственный
   способ убрать подлагивания UI.
4. **Приложения живут на microSD**, не во flash. Причина — 4 МБ flash и двойной OTA почти
   не оставляют места. Шрифты и картинки тоже на SD, иначе не влезем в слот прошивки.
5. **Двухслойная модель приложения:**
   - *Слой A (декларативный)* — `ui.jsonl` (layout в стиле openHASP) + описание источника
     данных (HTTP + путь к полю в JSON + период опроса). Без исполнения кода на устройстве.
     Закрывает погоду/курсы/табло — большинство виджетов. **Начинаем с него.**
   - *Слой B (скриптовый)* — Lua, только для виджетов с логикой (напоминания, помидор).
     Добавляем когда упрёмся в слой A.
6. **Двойной OTA с первого дня** — менять разметку потом означает полный реflash.
7. **Автономность обязательна.** Устройство должно работать при выключенном/спящем ПК.
   Каждое приложение объявляет capabilities (`net.http`, `time`, `storage`, `host`, `notify`).
   Виджеты без `host` обязаны быть полностью функциональны без ПК. Виджеты с `host` при
   отсутствии агента показывают последнее значение + отметку давности, не исчезают и не падают.
   **Напоминания живут на устройстве** (расписание в NVS/на SD, свой планировщик,
   сигнал через RGB-LED + динамик) — иначе главная фича умрёт вместе с компом.
8. **Тонкий HAL с первого дня.** У пользователя есть ESP32-C3 SuperMini как возможная
   вторая цель/спутник. Расплата за абстракцию нулевая, поэтому железо — только через BSP.

## Кнопки и комбинации

Пользователь хочет биндить действия на **комбинации** кнопок. Вариант A: 3 кнопки напрямую.

| Кнопка | Пин | Режим |
|---|---|---|
| B1 | GPIO22 | внутренний pull-up, кнопка на GND |
| B2 | GPIO27 | внутренний pull-up, кнопка на GND |
| B3 | GPIO35 | **только вход, внутренних pull-up нет** → внешний 10 кОм на 3V3 |

3 кнопки → 7 непустых масок × (короткое/длинное) = 14 действий + двойной клик + автоповтор.

**Окно разрешения хорда 50 мс** — нельзя выдавать событие сразу по нажатию, иначе `B1+B2`
всегда распознается как `B1`, затем `B2`. Опрос с антидребезгом 5 мс, накопление маски,
по истечении окна — фиксация. Цена: 50 мс задержки, для навигации незаметно.

Системные бинды (перехватывает оболочка, приложение их не видит):
`B1+B3` короткое = домой/лончер, `B1+B2` = яркость, `B1+B2+B3` длинное = настройки /
аварийный выход из зависшего виджета (обязательно — иначе кривой виджет запирает устройство).
Остальное отдаётся активному приложению; манифест объявляет желаемые бинды, конфликты
разрешает оболочка (система всегда выигрывает). Таблица биндов — JSON на SD / в NVS,
пользователь переназначает без перепрошивки.

### Фактическая раскладка: РАСПАЯНЫ ДВЕ КНОПКИ (B1, B2 на CN1)

`input_set_present_mask(INPUT_B1 | INPUT_B2)` в `main.c`. GPIO35 объявлен
отсутствующим и **не опрашивается вообще** — без внешних 10 кОм он бы плавал и
устройство жало бы себе B3 само.

Раскладка выбирается по маске в рантайме (`three_buttons()` в `shell.c`), потому что
без B3 нет отдельной клавиши «выбрать», и это сдвигает сразу несколько биндов:

| Действие | 2 кнопки | 3 кнопки |
|---|---|---|
| вверх / вниз | `B1` / `B2` | `B1` / `B2` |
| выбрать | **`B1+B2` коротко** | `B3` коротко |
| домой | `B1` длинно | `B1` длинно или `B1+B3` |
| яркость | `B2` длинно | `B1+B2` |
| аварийный выход | `B1+B2` длинно | все три длинно |

`B1` длинно = «домой» работает в **обеих** раскладках намеренно: это единственный
путь назад, доступный резистивному тачу, который однопальцевый и хорд не умеет.

### ⚠️ COM-порт НЕ фиксирован

Был COM13, после переподключения стал **COM4**. Windows раздаёт номер по USB-гнезду.
Скрипты определяют порт по имени устройства `USB-SERIAL CH340 (COMxx)`, а не по числу.

### ⚠️ RTS держит плату в ресете

RTS заведён на EN. Если закрыть COM-порт, не сняв RTS, чип остаётся в ресете, и
следующая прошивка падает с `No serial data received` **на исправном порту**.
Любой скрипт, трогающий последовательный порт, обязан перед закрытием сделать
`setRTS(False)` и `setDTR(False)`. Лечится переподключением USB.

Не сцеплять прошивку и чтение лога в одну команду без паузы — предыдущий читатель
ещё держит порт, и прошивка падает с `port is busy`.

### Состояние железа кнопок (историческое): БЫЛИ НЕ РАСПАЯНЫ

Пользователь хочет сначала сборку без кнопок. Паяльник, кнопки и резисторы есть;
в комплекте платы был **один 4-проводный JST-пигтейл**.

⚠️ **Тач резистивный (XPT2046) → одно касание, мультитач физически невозможен.**
Значит хорды через тач протестировать нельзя. Поэтому входной слой имеет три
взаимозаменяемых бэкенда, оболочка их не различает:
1. `gpio` — боевой, 3 кнопки (после пайки)
2. `touch_zones` — 3 зоны внизу экрана, **только одиночные** нажатия и long-press
3. `debug_inject` — синтетические события с ПК (serial/WS), **умеет любую маску** → хорды
   отлаживаем им до пайки

Первый шаг пайки, если понадобится: пигтейл на **CN1** (`GND · GPIO22 · GPIO27 · 3V3`) →
2 кнопки на внутренних pull-up, **без единого резистора**. Третья (GPIO35) потребует
разъём **P3** + внешний 10 кОм.

1664 КБ под LVGL + WiFi + TLS + Lua тесновато; держать шрифты и графику на SD.

### ⚠️ Дисплей: ST7789, а НЕ ILI9341 (выяснено на стенде, стоило ~7 итераций)

Плата продаётся как ESP32-2432S028**R** с ILI9341, но панель здесь на **ST7789**.
Подтверждено дважды: экспериментом и отзывами к товару. Наборы команд перекрываются
настолько, что чужой драйвер «почти работает» — и именно это сбивает с толку.

Итоговая рабочая конфигурация (проверена фотографией экрана: рамка сомкнута по всем
четырём краям, диагональ из угла в угол прямая):

| Параметр | Значение | Как выяснено |
|---|---|---|
| Драйвер | `esp_lcd_new_panel_st7789` | под ILI9341 адресное окно заворачивалось: неполная заливка, дублирование маркеров, полосы |
| Ориентация | `swap_xy=1, mirror_x=1, mirror_y=0` | перебор 5 комбинаций; правильная = поворот на 180° от той, что видел пользователь |
| Порядок каналов | **RGB**, не BGR | под BGR красный и синий менялись местами. Большинство материалов по CYD утверждает BGR — для этой партии неверно |
| Порядок байт | `swap_bytes = true` в `esp_lvgl_port` | LVGL кладёт RGB565 как little-endian uint16, панель ждёт старший байт первым |
| Частота SPI | **20 МГц** (проверено) | 40 МГц не проверялась под ST7789; поднимать только глядя на разрывы кадра |
| `x_gap`/`y_gap` | **не нужны** | рамка касается всех краёв, смещения нет |

Диагностика осталась в `main.c` под `#define DESKOS_DISPLAY_DIAG` — перебор драйверов,
ориентаций, цветовых кодировок и чёрно-белый тест геометрии. Включается одной цифрой.

⚠️ **Разворот задаётся В ДВУХ МЕСТАХ и они обязаны совпадать:** `bsp_display_init(landscape=true)`
и поле `.rotation` в `lvgl_port_display_cfg_t` (`shell.c`). Причина: `lvgl_port_add_disp`
**сам вызывает** `esp_lcd_panel_swap_xy`/`mirror` со своими значениями и затирает то, что
выставил BSP. Оставишь `.rotation` по умолчанию (всё false) — панель вернётся в портрет
240×320, а LVGL продолжит считать экран 320×240: интерфейс выйдет повёрнутым на 90° с
остатками старого кадра в незакрытой области. «Двойного разворота» бояться не нужно —
это абсолютные сеттеры, а не относительные повороты.

Меняешь ориентацию — правь **оба** места одновременно.

**Грабли, на которые я наступил (не повторять):**

1. **`max_transfer_sz` в конфиге SPI-шины ограничивает ОДИН `draw_bitmap`, а не только
   flush из LVGL.** Передача сверх лимита **отвергается целиком**, и узнать об этом можно
   только по коду возврата. Я его не проверял → два теста подряд молча показывали остатки
   предыдущего кадра, и я искал причину совсем не там. Теперь лимит с запасом (80 строк),
   а `draw_bitmap` проверяется.
2. **Нельзя диагностировать геометрию по цветам, пока сама кодировка цвета под вопросом.**
   Разделять: геометрию проверять чёрно-белым (эти два значения одинаковы при любом
   порядке байт и каналов), цвет — отдельно, на заведомо верной геометрии.
3. **Словесное описание экрана — плохой канал передачи данных.** Семь итераций ушло на то,
   что одна фотография закрыла за минуту. Просить фото сразу.
4. **«Бледное, засвеченное» было ДВУМЯ разными проблемами** — перепутанными каналами и
   засветкой подсветки сквозь чёрный пиксель. Второе не лечится драйвером: у панели
   слабый чёрный, на 100% яркости тёмная тема выглядит блёкло-синей. Дефолт снижен до 55%.

### Проверено на живой плате (первая прошивка, 17.08.2026)

Разметка применилась, устройство загружается и работает:

| Замер | Значение |
|---|---|
| Free heap до инициализации | 243 624 Б |
| **Free heap после полной загрузки** | **176 128 Б (172 КБ)** |
| Стоимость LVGL + дисплей + тач + FS | ~66 КБ |

⚠️ 172 КБ — это **весь оставшийся бюджет RAM** на WiFi (~50–60 КБ), TLS и приложения.
Без PSRAM это главное ограничение проекта. Каждый новый буфер считать.

Хорд-движок **проверен на железе**, все 7 сценариев декодированы верно, включая
двойной клик, длинное нажатие с автоповтором и аварийный `B1+B2+B3` long.
Отсутствие microSD обрабатывается корректно: `sdmmc_card_init failed (0x107)` →
предупреждение → оболочка поднимается и сообщает об отсутствии карты.

Три ловушки Kconfig, уже пойманные (не наступать снова):
- **`sdkconfig.defaults` не применяется к уже существующему `sdkconfig`.** Добавили
  новый символ в defaults — надо удалить `sdkconfig` и пересобрать, иначе правка
  молча не подействует. Именно так впервые не сработал `SPI_FLASH_SUPPORT_BOYA_CHIP`.
- `CONFIG_FATFS_CODEPAGE_1251` **не существует** в IDF. Кириллических вариантов
  только OEM-866; Windows-1251 нет. Нам не нужно — имена папок приложений латиница.
- `CONFIG_ESP_SYSTEM_PANIC_*` — это Kconfig `choice`. Член choice нельзя выставить
  в `n`, выбирается другой член в `y`. Оставлено по умолчанию (print + reboot).

```
bsp       железо: дисплей, тач, SD, LED. Единственное место с номерами пинов
input     кнопки, хорды, три бэкенда ввода
registry  реестр приложений. ОТДЕЛЬНЫЙ компонент: нужен и shell'у, и widget'у,
          внутри любого из них дал бы циклическую зависимость
widget    рантайм слоя A: разбор ui.jsonl, HTTP-источник, подстановка {{path}}
net       WiFi STA + SNTP, автопереподключение с backoff
shell     лончер, статус-бар, системные комбинации
```

### Встроенные приложения распаковываются, а не компилируются

`main/builtin/*` вшиты через `EMBED_TXTFILES` и при старте выкладываются в
`/fs/apps/<id>/`. Можно было бы рисовать их вкомпиленным C, но тогда путей запуска
виджета стало бы два, а проверялся бы только один. Так загрузчик один — файловый,
и устройство полезно ещё до появления microSD.

Реестр сканирует **два корня**: `/fs/apps` (встроенные) и `/sd/apps` (пользовательские).

⚠️ `EMBED_TXTFILES` дописывает NUL, и символ `_end` его считает. Длина = разность
минус 1, причём вычитать надо **из разности**: `_end - 1` компилятор читает как
индекс −1 внешнего массива и валит сборку по `-Werror=array-bounds`. См. `EMB_LEN`.

### Учёт памяти после подключения WiFi

| Замер | Было (без сети) | Стало |
|---|---|---|
| `deskos.bin` | 625 КБ | **1382 КБ из 1664 КБ (свободно 17%)** |
| Free heap после загрузки | 175 864 Б | **125 340 Б** |
| Free heap с поднятым WiFi | — | **80 440 Б** |

⚠️ 80 КБ — это реальный остаток при подключённой сети. Рукопожатие TLS даёт пик
~40 КБ, то есть запас примерно двукратный. Каждый новый буфер считать.

⚠️ **Флеш стал узким местом.** WiFi + mbedTLS + полный bundle сертификатов дали
+750 КБ. На слой B (Lua, ~200 КБ) остаётся 282 КБ — влезет впритык.
Чем добирать при нехватке: `CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_DEFAULT_CMN` вместо
полного бандла (~40 КБ), отключение неиспользуемых шифров mbedTLS.

Heap: 125 КБ, из них рукопожатие TLS съедает пик ~40 КБ. Поэтому буфер LVGL
уменьшен с 40 строк до 24 (30 КБ на две буферы вместо 50).

### Учётные данные WiFi

Приоритет: NVS → `CONFIG_DESKOS_WIFI_SSID`/`_PASSWORD` из `sdkconfig`.
`sdkconfig` **не** в git, поэтому пароль туда не утекает в репозиторий.
Пароль в лог не пишется никогда. Рантайм-путь — `net_set_credentials()`.

## План работ

Разбит по фазам с критериями готовности в [ROADMAP.md](ROADMAP.md).
Рекомендованный порядок: часы → тесты рендерера на хосте → преобразования
значений в слое A → кеш данных на карте → протокол ПК-агента.

⚠️ **Кириллица отложена по решению пользователя** — русский текст пока не нужен,
а шрифт стоил бы 30–60 КБ флеша, которого и так в обрез. Интерфейс на латинице
**намеренно**, это не недоделка.

## Открытые вопросы

- ~~Кириллический шрифт~~ — **отложено осознанно**, см. выше. Не «починить при случае»
- **Протокол с ПК-агентом** (mDNS + WebSocket) не начат. Capability `host` объявляется
  в манифестах, но источника данных за ней ещё нет
- **Слой B (Lua)** не начат. На него остаётся ~280 КБ флеша при потребности ~200 КБ —
  влезет впритык, сперва стоит ужать mbedTLS
- **Калибровка тача**: в `bsp_touch.c` типовые константы, реальные не снимались.
  Тач работает, но точность на краях не проверялась
- **40 МГц SPI** не проверялась под ST7789, стоит 20
- **Третья кнопка** (GPIO35 + внешние 10 кОм) не распаяна; код к ней готов,
  включается одной строкой `input_set_present_mask` в `main.c`
- Консольный шим для `debug_inject` через UART не сделан (риск конфликта с консолью
  на UART0)

## Что НЕ делать

- Не флэшить, не стирать flash и не менять разметку без явного подтверждения пользователя
  (на плате до сих пор живёт та погодная станция; бэкап есть, но спрашивать всё равно)
- Не публиковать дамп flash — в нём пароль WiFi
- Не открывать COM13 сторонними программами во время работы устройства — DTR/RTS ребутнёт плату
- Не вкомпиливать шрифты/картинки в прошивку — не влезем
- Не тянуть Arduino-совместимость «на всякий случай»
