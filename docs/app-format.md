# Формат приложения-виджета (API 1)

Приложения живут на **microSD**, не во flash. Причина: у платы 4 МБ flash, и двойной
OTA-слот занимает почти всё. Шрифты и картинки — тоже на SD.

```
/sd/apps/<id>/
    manifest.json     обязателен
    ui.jsonl          слой A: декларативный интерфейс
    main.lua          слой B: логика (пока не реализован)
    icon.bin          опционально, LVGL binary image
```

«Установка» приложения = скопировать папку на карту. Никакой перепрошивки и компиляции.

## manifest.json

```json
{
  "api": 1,
  "id": "weather",
  "name": "Weather",
  "version": "1.0.0",
  "layer": "declarative",
  "entry": "ui.jsonl",
  "capabilities": ["net.http", "time"],
  "poll_sec": 900
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `api` | да | Версия контракта. Оболочка **отказывается** грузить незнакомую версию, а не пытается разобрать наполовину. |
| `id` | да | Латиница, уникален. По умолчанию — имя папки. |
| `name` | да | Отображаемое имя. ⚠️ Пока только латиница (см. ниже). |
| `version` | нет | Семвер, для будущих обновлений. |
| `layer` | нет | `declarative` (по умолчанию) или `lua`. |
| `entry` | нет | Точка входа, по умолчанию `ui.jsonl`. |
| `capabilities` | нет | См. таблицу ниже. Не объявил — не получил. |
| `poll_sec` | нет | Период обновления данных. |

⚠️ **Кириллица в `name` пока не отрисуется.** Встроенные шрифты Montserrat в LVGL
содержат только ASCII/Latin-1 и символы, глифов кириллицы там нет. Нужен шрифт,
сгенерированный `lv_font_conv`. Это открытая задача.

## Capabilities

| Значение | Даёт | Поведение без ПК |
|---|---|---|
| `net.http` | HTTP(S)-запросы наружу | работает, нужен только WiFi |
| `time` | локальное время, таймеры, будильники | работает |
| `storage` | чтение/запись в своей папке | работает |
| `host` | данные от ПК-агента (протокол — [docs/host-protocol.md](host-protocol.md), не реализовано) | **недоступно**, см. ниже |
| `notify` | RGB-LED и динамик | работает |

### Правило автономности

Устройство обязано быть полезным при спящем или выключенном ПК. Поэтому:

1. Приложение **без** `host` обязано быть полностью функционально без ПК.
2. Приложение **с** `host` при отсутствии агента **не исчезает** из лончера — оно
   помечается как недоступное и показывает последнее полученное значение с отметкой
   давности. Падать и показывать пустоту нельзя.
3. Напоминания и будильники живут **на устройстве** (расписание на SD/в NVS, свой
   планировщик, сигнал через LED и динамик). Держать их на ПК нельзя — умрут вместе с ним.

## Бинды на кнопки

Три кнопки → 7 непустых масок × (короткое/длинное) = 14 действий, плюс двойной клик
и автоповтор при удержании.

Системные комбинации оболочка забирает себе, приложение их **не видит**:

| Комбинация | Действие |
|---|---|
| `B1+B3` коротко | домой / лончер |
| `B1+B2` коротко или автоповтор | яркость по кругу |
| `B1+B2+B3` длинно | аварийный выход из зависшего виджета |

Остальное приложение запрашивает в манифесте полем `bindings` — объект
«строка события» → «имя действия»:

```json
"bindings": {"B1+B2 click": "refresh"}
```

Ключ — ровно то, что показывает `input_event_str()` в логе (`"input: B1+B2
click"` и т.п.): маски кнопок через `+` (`B1`, `B2`, `B3` в любом порядке),
пробел, одно из `click`/`dblclick`/`long`/`repeat`/`release`. Не распарсился
ключ или неизвестно имя действия — строка молча пропускается с предупреждением
в лог, остальной манифест не страдает, тот же принцип, что и у остального
формата (одна кривая строка не должна валить всё приложение).

Слой A не исполняет код, поэтому действие — не произвольный обработчик, а
одно из фиксированного набора, который умеет сам рантайм. Пока единственное:

| Действие | Что делает |
|---|---|
| `refresh` | форсирует немедленный повторный запрос всех `http`-источников виджета, в обход `every`. На host-темы не влияет — агент шлёт данные сам, поторопить нельзя. На экране сразу появляется `refreshing...` в углу, до завершения запроса |

Конфликты с системными комбинациями разрешать отдельно не нужно: оболочка
проверяет их первыми (см. таблицу выше) и только потом — бинды текущего
открытого виджета, поэтому запрошенная в манифесте комбинация, занятая
системой, просто никогда не сработает — без отдельной таблицы конфликтов.

⚠️ Переназначение биндов пользователем (через NVS, отдельно от того, что
просит манифест) не реализовано — сейчас работает только то, что явно
объявило приложение.

## Слой A — `ui.jsonl`

JSON Lines: одна строка = один объект. Формат в духе openHASP, сознательно —
изобретать свой смысла нет.

```jsonl
{"obj":"label","x":8,"y":8,"text":"{{current.temperature_2m}} C","font":28}
{"obj":"label","x":8,"y":48,"text":"{{daily.temperature_2m_max.0}} / {{daily.temperature_2m_min.0}}"}
{"src":"http","url":"https://api.open-meteo.com/v1/forecast?latitude=55.75&longitude=37.62&current=temperature_2m","every":900}
```

Ключевая идея: **на устройстве не исполняется код приложения**. Есть layout и есть
привязка полей к путям в JSON-ответе. Этим закрывается большинство виджетов —
погода, курсы, любые REST-табло — при минимальном расходе RAM, которой на этой плате
всего ~300 КБ.

⚠️ **Верхние ~16px экрана зарезервированы под системный тулбар** (часы,
wifi/sd/pc — см. [docs/shell-navigation.md](shell-navigation.md)), он рисуется
поверх любого открытого виджета. Не класть туда важный контент и подбирать
цвет фона так, чтобы иконки поверх были читаемы.

### Типы видов (`obj`)

Общие для всех: `x`, `y` — позиция левого верхнего угла.

| `obj` | Поля | Замечания |
|---|---|---|
| `label` | `text`, `font` (14/20/28/48), `color` (`"0xRRGGBB"`), `w` (перенос строк), `align` (`"center"`, только вместе с `w`), `scale` | `text` — шаблон `{{path}}`, обновляется на каждый refresh |
| `rect` | `w`, `h`, `color`, `radius`, `border_width`, `border_color` | сплошная плашка/фон, без данных; `radius` — скругление углов в пикселях, `border_width`/`border_color` — рамка (без `border_width` рамки нет) |
| `line` | `x1`,`y1`,`x2`,`y2`, `color`, `width` | статичный разделитель; координаты точек — относительно `x`/`y`. Данных не показывает |
| `bar` | `w`, `h`, `min`, `max`, `value`, `color` | `value` — тот же `{{path}}`-шаблон, что `text` у label, но приводится к числу |
| `arc` | `w`, `h`, `min`, `max`, `value`, `color` | то же самое, что `bar`, по кругу; не интерактивна (тач её не двигает) |
| `image` | `src` | `.bin`-картинка в формате LVGL (не PNG/JPG!) из папки приложения (проверено на живой плате, ROADMAP #34/#35); `src` тоже может быть шаблоном `{{path}}` — файл выбирается заново на каждый refresh. ⚠️ Нет способа уменьшить картинку на устройстве: `lv_image_set_scale()` рушит отрисовку в этой сборке (иконка молча не рисуется вовсе — воспроизведено и подтверждено на живой плате, причина внутри LVGL не докопана, слишком дорого). Нужен размер меньше исходного — конвертировать отдельный набор `.bin` тем же `tools/icon_convert.py` с другим `size_px`; учесть, что второй набор — это второй словарь путей в `ui.jsonl`, а словари живут в куче на всё время открытия виджета (см. CLAUDE.md про #40 — на этой памяти уже упирались) |

`value`/`text`/`src` без `{{...}}` вообще — то есть голое статическое значение —
тоже работает и рисуется один раз при открытии виджета, даже если у виджета нет
источника данных вовсе.

### `scale` — увеличение текста крупнее самого большого шрифта

`48` — самый большой шрифт LVGL, встроенный в эту сборку (ROADMAP #39), но
даже он не «на весь экран». Поле `scale` у любой вьюхи (проверено только на
`label`) растягивает её через LVGL-трансформацию — процент, `100` — без
изменений, `200` — вдвое по обеим осям:

```jsonl
{"obj":"label","x":0,"y":64,"w":320,"align":"center","font":48,"scale":200,"text":"{{time}}"}
```

Трансформация не меняет раскладку — увеличенная отрисовка растёт от точки
опоры (pivot), а не переcчитывает `x`/`y`/`w`. По горизонтали опора — центр
объявленного `w` (то есть `scale` растёт симметрично влево-вправо ровно тогда,
когда рядом стоит `align":"center"` — та же пара, что уже нужна для обычного
центрирования). По вертикали опора всегда верхний край — вертикальное
центрирование `scale` пока не поддержано, потому что никому не понадобилось.
Без `w` опора по горизонтали — левый край, увеличение растёт только вправо.

⚠️ Это отдельный от `lv_image_set_scale()` механизм LVGL (стилевая
трансформация, а не поле `scale` самого image-виджета) — тот, что рушит
отрисовку картинок в этой сборке (см. `image` в таблице выше), сюда не
относится. Обратное не проверено само собой: `scale` на `label` подтверждён
на живой плате (`clock`, ROADMAP #39), на `rect`/`bar`/`arc`/`image` — нет,
хотя поле обрабатывается для любого вида одинаково.

### Преобразования значений — фильтры

Голая подстановка `{{path}}` часто недостаточна. Внутри `{{...}}` путь можно
пропустить через цепочку фильтров через `|`:

```jsonl
{"obj":"label","text":"{{current.temperature_2m | round:0}} C"}
{"obj":"label","text":"{{current.weather_code | dict:weather_code}}"}
{"obj":"label","text":"{{current.apparent_temperature | sub:current.temperature_2m | round:1}}"}
```

| Фильтр | Аргумент | Что делает |
|---|---|---|
| `round` | `N` (0–6) | округляет число до `N` знаков после запятой |
| `add` / `sub` / `mul` / `div` | число или путь | арифметика; так же выглядит перевод единиц: `\| mul:0.621` — км/ч в мили/ч. Деление на 0 — no-op |
| `dict` | имя словаря | подстановка по таблице, см. ниже |
| `date` | строка формата `strftime` | перепарсивает `YYYY-MM-DD` или `YYYY-MM-DDTHH:MM` и форматирует заново, включая день недели (`%a`/`%A`) |

Фильтр на значении не того типа (округление строки, словарь без такого имени,
неизвестное имя фильтра, дата не в распознанном формате) — **no-op**: значение
проходит как было, а не превращается в `--`. Тот же принцип, что и у пропавшего
поля — виджет с одной сломанной строкой не должен гаснуть целиком.

**Словари** объявляются отдельной строкой, до первого использования:

```jsonl
{"dict":"weather_code","map":{"0":"Clear sky","1":"Mainly clear","3":"Cloudy"}}
```

Ключ словаря — всегда строка (даже если исходное значение — число, оно сначала
приводится к тексту). Код, не найденный в словаре, показывается как есть —
это осознанно: недостающая строка в словаре не должна прятать данные.

### Условная видимость

Отдельное поле `if` у любой вьюхи (не через `|`, просто путь):

```jsonl
{"obj":"label","if":"current.precipitation","text":"rain: {{current.precipitation}} mm"}
```

Вьюха скрывается, когда путь резолвится в «пусто»: значения нет, `false`,
`0`, `""`, `"0"`, `"false"` или пустой массив/объект — всё остальное истинно.
До первого обновления данных вьюха с `if` скрыта по умолчанию.

### Несколько страниц и `tap`

Поле `page` у любой вьюхи ограничивает её одной «страницей» — целым числом,
своим для каждой вьюхи:

```jsonl
{"obj":"label","text":"current","page":0}
{"obj":"label","text":"forecast","page":1}
```

Вьюха без `page` вообще (как у всех виджетов до ROADMAP #40) показывается
всегда, вне зависимости от активной страницы — старые `ui.jsonl` этой
возможностью не затронуты. Активная страница начинается с `0`; переключает
её единственное на сегодня действие тача — `"tap":"next_page"` на любой
вьюхе (обычно — на общем для всех страниц заголовке):

```jsonl
{"obj":"rect","x":0,"y":18,"w":320,"h":44,"color":"0x1E2A38","tap":"next_page"}
```

Касание переключает страницу по кругу до максимального номера `page`,
встреченного в файле, и обратно на `0`. Любая вьюха без `tap` — не
кликабельна (LVGL по умолчанию делает кликабельным всё; здесь это явно
выключено), иначе лежащая сверху надпись/иконка перехватывала бы касание,
адресованное вьюхе под ней — тач резистивный и однопальцевый, второй попытки
попасть именно в пустое место может не быть. `tap` — фиксированный небольшой
набор имён действий, как у клавишных `bindings` (ROADMAP #16): неизвестное
имя — тихий no-op, тот же принцип, что у неизвестного фильтра. Пока
единственное действие — `next_page`; остальные заводить по мере реальной
надобности, не заранее.

⚠️ Тапаемый `rect` при касании заметно светлеет (LVGL `LV_STATE_PRESSED`) —
без этого палец не может отличить «попал, но действие ничего не поменяло» от
«вообще не попал», что на резистивном тач-панеле с его известной неточностью
(см. CLAUDE.md про калибровку) оказалось реальной проблемой при отладке
ROADMAP #39. Мелкие тапаемые цели всё равно ненадёжны на этом экране —
проверено там же: маленькая плашка ~78×32px в углу экрана оказалась
достаточно сложной целью, чтобы саму настройку в итоге унести с лица виджета
в Settings (см. ниже про `{"src":"clock"}`). Полноэкранный `rect`, как в
примере выше, гораздо безопаснее любой мелкой кнопки.

Активная страница сохраняется в NVS по ключу `pg_<id приложения>` и переживает
переоткрытие виджета и перезагрузку устройства — то есть это не эфемерный
режим просмотра, а настоящая, хоть и негласная, настройка. Виджет без `page`
вообще эту запись не создаёт.

### Источники: `http` и локальные

`{"src":"http",...}` — то, что описано выше. Наряду с ним есть **локальные**
источники: данные не приходят по сети, а вычисляются самой оболочкой.

```jsonl
{"src":"clock"}
```

Даёт поля `time` (`HH:MM`, 24-часовой), `time12` (`H:MM`/`HH:MM`, 12-часовой,
без ведущего нуля), `ampm` (`AM`/`PM`), `h24`/`h12` (булевы, взаимно
противоположны — для `if`), `date` (`DD Mon YYYY`) и `weekday` (`Mon`…`Sun`,
латиница — см. «Открытые вопросы» в CLAUDE.md про кириллицу). Обновляется раз
в секунду и не требует WiFi — источник берёт системное время, выставленное
SNTP при последней удачной синхронизации. До первой синхронизации после
холодного старта поля отсутствуют (рендерятся как `--`), в статусной строке
виджета — «waiting for time sync».

`h24`/`h12` управляются одной глобальной настройкой — Settings → Display →
«12-hour clock» (ROADMAP #39; `widget_clock_h24()`/`widget_set_clock_h24()`
в `widget.h`, хранится в NVS под `clock_h24`) — общей для любого виджета с
`{"src":"clock"}`, а не своей у каждого. Типичная разметка — две вьюхи на
одной позиции, разведённые через `if`:

```jsonl
{"obj":"label","x":0,"y":64,"w":320,"align":"center","font":48,"scale":200,"text":"{{time}}","if":"h24"}
{"obj":"label","x":0,"y":64,"w":320,"align":"center","font":48,"scale":200,"text":"{{time12}}","if":"h12"}
```

Несколько `http`-источников в одном виджете разрешены, каждый со своим URL и
периодом опроса:

```jsonl
{"src":"http","url":"https://api.open-meteo.com/v1/forecast?...","as":"weather","every":900}
{"src":"http","url":"https://api.frankfurter.dev/v1/latest?from=USD&to=EUR","as":"fx","every":3600}
{"obj":"label","x":8,"y":8,"text":"{{weather.current.temperature_2m}} C / {{fx.rates.EUR}} EUR"}
```

`as` даёт источнику имя — его тело кладётся под этот ключ (`weather.current...`,
`fx.rates...`), поэтому несколько источников не перезаписывают друг друга.
Источник без `as` по-прежнему расстилается на верхний уровень документа, как
раньше, — старые файлы с одним источником правок не требуют. Источники опрашиваются
независимо: если один упал, остальные всё равно обновляются, а виджет помечает
себя `stale`, только если сорвался хотя бы один из тех, кому в этот раз настало
время фетчиться.

⚠️ `http` и локальный источник (`clock`) в одном `ui.jsonl` по-прежнему не
комбинируются — манифест, объявляющий и то и другое, получает `clock` (не
зависит от сети). Несколько `http`-источников с `clock` сразу — тоже не
поддерживается.

### Настройка виджета: `data` и `config`

Виджету часто нужен параметр, который пользователь должен уметь поменять без
переустановки — город для погоды, тикер для курса акций — но который не
должен требовать правки `ui.jsonl` на карте. Две простые строки решают это
вместе:

```jsonl
{"data":{"name":"Plovdiv","lat":"42.14","lon":"24.75"}}
{"src":"config","path":"/sd/weather.json"}
{"src":"http","url":"https://api.open-meteo.com/v1/forecast?latitude={{lat}}&longitude={{lon}}&...","every":900}
```

`data` — литеральный объект, вписывается в общий документ один раз при
разборе `ui.jsonl` (не обновляется, это не полноценный источник). Обычно —
встроенные умолчания, чтобы виджет работал сразу после установки, без единой
настройки.

`src: config` — то же самое, но из файла (обычно на SD, туда же, куда пишет
веб-конфиг — см. `components/webcfg`), прочитанного один раз при открытии
виджета. Файла нет или он битый — не ошибка, просто ничего не подставляется,
и в силе остаётся то, что объявил `data` (или пустое поле, если `data` не
было).

Объявленные так поля становятся доступны для **шаблонов в `url` самого
`http`-источника**, не только для `text`/`value` вьюх — `{{lat}}`/`{{lon}}`
выше резолвятся в момент разбора `ui.jsonl`, до первого запроса. Порядок строк
важен: `data`/`config` должны стоять раньше `http`-строки, которая на них
ссылается, — они разбираются по порядку сверху вниз, как и весь файл. `url`
без `{{...}}` работает как раньше, так что старые файлы этой возможностью не
затронуты.

### Источник `host` (capability `host`, протокол — docs/host-protocol.md)

```jsonl
{"src":"host","topic":"cpu"}
{"obj":"label","x":8,"y":8,"text":"CPU {{cpu.percent}}% / {{cpu.temp_c}} C"}
```

Данные не запрашиваются, а приходят пушем от ПК-агента (если он настроен и
доступен — см. `/sd/agent.json` в CLAUDE.md) через общего фонового клиента
устройства, один на всё устройство, не по соединению на виджет. `topic`
обязателен и всегда даёт название ветке в документе — в отличие от `http`,
здесь нет безымянного варианта, расстилающего поля на верхний уровень.
Можно объявить несколько строк `host` с разными темами в одном виджете, и
вперемешку с `http`-источниками — оба пишут в один и тот же документ.
`clock` по-прежнему исключение: если объявлен, побеждает он один.

Пока агент не подключился (или не настроен вовсе) — виджет статусом
`waiting for pc` честно говорит, что данных ждать неоткуда, но виджет не
пропадает из лончера. Данные по темам на диск не кешируются (в отличие от
`http`, №11) — при перезапуске виджета начинается с чистого листа, ждать
агента заново.

### Кеш на диске

Каждый успешный фетч (объединённый документ всех источников сразу, не по
одному) сохраняется в `<dir приложения>/.cache.json`. При следующем открытии
виджет читает этот файл ещё до первой попытки сети — значит, при спящем ПК
или лежачем роутере на экране сразу оказываются вчерашние данные, а не
пусто. Статус в углу честно показывает возраст (`cached 5m ago`, `cached 2h
ago`, ...) до тех пор, пока не придёт первый живой ответ в эту сессию.
Файл — деталь реализации рантайма, `ui.jsonl` его не объявляет и не должен
использовать имя `.cache.json` для чего-то своего.

## Слой B — Lua

Для виджетов с логикой: напоминания, помидор, игры. Добавляется, **когда слой A
упрётся**, не раньше. Lua выбран за размер (~150–200 КБ flash) — на плате без PSRAM
это единственный реалистичный вариант скриптования.
