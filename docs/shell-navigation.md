# Навигация оболочки (ROADMAP №6)

Дизайн-документ, не код. Закрывает задачу №6: экраны и переходы между ними
решены здесь, до того как под них начнут переписывать `shell.c`. Отрисовка
самого виджета (`widget_open`) этим документом не затронута и не меняется.

## Экраны

### Home
Полноэкранный рендер **одного** виджета из закреплённых — переиспользует
существующий `widget_open()`, никакого нового движка рендера не нужно.
`B1`/`B2` коротко — переключение на предыдущий/следующий закреплённый виджет
(не список, прямое пролистывание). Если закреплённых нет (свежая установка,
ничего не выбрано) — статичная заглушка «нет закреплённых виджетов, откройте
Full list».

Планируется отдельно, не сейчас: автопрокрутка закреплённых по таймеру
(режим витрины, №19) с переключателем вкл/выкл в Settings.

### Full list
Сетка плашек вместо текущего вертикального списка. Каждая плашка — прямоугольник
+ имя приложения (те же примитивы, что уже рисует лончер сегодня). Источники:
всё из `app_registry` (SD + встроенные) плюс одна синтетическая плашка **Settings**,
которую лончер добавляет сам, не из реестра.

`B1`/`B2` коротко двигают курсор по плашкам в порядке регистрации в LVGL-группе —
это уже работающий код (`lv_group` + `LV_KEY_PREV`/`NEXT`), меняется только
визуальная раскладка (сетка вместо колонки), сама навигация не переписывается.
`B1`+`B2` коротко открывает подсвеченную плашку: обычное приложение — через
`widget_open`, плашка Settings — открывает нативный экран настроек (не через
движок виджетов слоя A).

Иконок с картинкой на плашках пока не будет — их физически нет (см. №28,
формат `image` есть в коде, ни одной готовой иконки в проекте нет). Когда
появятся — текст на плашке меняется на картинку, сетка не переделывается.

### Settings (№7)
Нативный экран, отдельная реализация (не `ui.jsonl`). Помимо яркости/пояса/
WiFi/карты/памяти/версии (уже описанных в №7), сюда же добавляется:
- **чек-лист приложений** — отметить, какие закреплены на Home. Единственный
  способ закрепить/открепить — через этот чек-лист, не через комбинацию кнопок
  на Full list (свободных комбинаций для этого не осталось, см. ниже).
- переключатель автопрокрутки Home (когда появится №19).

### Widget (открытое приложение)
Без изменений — `widget_open()`/`widget_close()` как сегодня. Не отличает,
был ли он открыт как содержимое Home или запущен из Full list.

## Переходы между экранами

| Откуда | Действие | Куда |
|---|---|---|
| (загрузка) | — | Home |
| Home | `B1`+`B2` коротко | Full list |
| Full list | `B1`+`B2` коротко на плашке приложения | Widget |
| Full list | `B1`+`B2` коротко на плашке Settings | Settings |
| Любой экран | `B1` длинно | **всегда Home** |

`B1` длинно и раньше означало «домой» (закрыть открытый виджет и вернуться в
лончер) — теперь «домой» становится настоящим экраном вместо неявного
«ничего не открыто», сама комбинация не меняется.

## Глобальный тулбар

Часы + иконки состояния (`wifi`/`sd`/`pc`/бэкенд ввода) — **общий слой поверх
всех экранов**, включая Home, Full list, Settings и любой открытый виджет.
Реализуется через `lv_layer_top()` в LVGL: один объект, одна точка
обновления, виден всегда, не зависит от того, какой экран сейчас активен
(`lv_screen_load`). Без этого статус-бар пропадал бы всякий раз при открытии
виджета, как это происходит сегодня.

- Иконки — через встроенные символьные глифы LVGL (`LV_SYMBOL_WIFI`,
  `LV_SYMBOL_SD_CARD` и т.п.), без файлов и без пайплайна изображений.
- Часы — та же логика, что у виджета `clock` (`time()`/`localtime_r()`),
  но напрямую в коде тулбара, не через движок слоя A; обновление раз в
  секунду отдельным `lv_timer`.
- Объекты тулбара не кликабельны — не участвуют в LVGL-группе, не мешают
  навигации по текущему экрану.
- ⚠️ Авторам виджетов: верхние ~16px экрана визуально перекрываются тулбаром.
  Разметку `ui.jsonl`, которая сейчас кладёт контент в самый верх (например,
  заголовочный `rect` в `weather.ui.jsonl` с `y:0`), при переходе на тулбар
  стоит сдвинуть вниз или подобрать контрастный цвет под иконками.

## Что сознательно не решено здесь

- Точный набор символов тулбара и цвета — решается при реализации №7/переверстке
  лончера, не меняет схему переходов.
- Закрепление/открепление через сам Full list (например, долгим нажатием на
  плашке) — рассматривалось и отклонено: свободных комбинаций кнопок не
  осталось, а делать системные комбинации (`B1+B2` длинно — сейчас аварийный
  выход) чувствительными к текущему экрану ломает принцип «система всегда
  одна и та же независимо от экрана». Если чек-лист в Settings окажется
  неудобным на практике — вернуться к этому вопросу отдельно.
