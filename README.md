# deskos

Оболочка настольного помощника для **ESP32-2432S028R** («Cheap Yellow Display», 2.8", 320×240).

Устройство постоянно стоит на столе под питанием. Оболочка работает как мини-ОС: лончер,
список виджетов, пользователь сам ставит приложения копированием папки на microSD —
без перепрошивки и без компиляции.

Подробности железа, принятые решения и ограничения платы — в [CLAUDE.md](CLAUDE.md).
Формат приложений — в [docs/app-format.md](docs/app-format.md).

## Сборка

Нужен ESP-IDF **5.5.x**. Активация окружения:

```bash
powershell -ExecutionPolicy Bypass -NoProfile -NoExit -File C:\esp\esp-idf\export.ps1
```

Затем:

```bash
idf.py set-target esp32
idf.py build
```

Прошивка и монитор (плата на COM13):

```bash
idf.py -p COM13 flash monitor
```

⚠️ Первая прошивка **заменит разметку flash** (заводская была `huge_app` без второго
OTA-слота). Бэкап заводской прошивки и команда восстановления — в CLAUDE.md.

## Структура

```
components/bsp/      железо: дисплей, тач, SD, LED. Единственное место с номерами пинов.
components/input/    кнопки, комбинации (хорды), три взаимозаменяемых бэкенда ввода
components/shell/    лончер, реестр приложений
main/                инициализация
apps/                примеры виджетов (копируются на карту в /sd/apps/)
partitions.csv       двойной OTA + LittleFS под 4 МБ
```

## Состояние

Готово:

- BSP: ILI9341 через `esp_lcd` на SPI2, XPT2046 программным SPI, microSD на SPI3,
  подсветка через LEDC, RGB-LED
- Входной слой: антидребезг, окно разрешения хорда, короткое/длинное/двойное нажатие,
  автоповтор; бэкенды `gpio` / `touch_zones` / `debug_inject`
- Оболочка: статус-бар, лончер на LVGL 9, LVGL keypad + pointer indev,
  системные комбинации, реестр приложений с чтением `manifest.json`
- Разметка flash с двойным OTA

Не готово:

- интерпретатор слоя A (`ui.jsonl`) — приложения пока только перечисляются
- слой B (Lua)
- WiFi, SNTP, HTTP-источники данных
- протокол с ПК-агентом (mDNS + WebSocket)
- кириллический шрифт (во встроенном Montserrat глифов кириллицы нет)
- калибровка тача и её сохранение
- кнопки физически не распаяны

## Известные ограничения платы

Две вещи, которые определяют всю архитектуру и объясняются в CLAUDE.md:

1. **Тач и SD висят на разных наборах пинов одной номинальной шины**, а свободных
   SPI-контроллеров у ESP32 два на три периферии. Поэтому тач — на программном SPI.
2. **CH340 перезагружает плату при открытии COM-порта** (схема авто-ресета по DTR/RTS).
   Поэтому канал к ПК-агенту — по WiFi, а USB только для прошивки и логов.
